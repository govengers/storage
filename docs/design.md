# govengers/storage: design

Status: first version, 15.11.2026. Decisions are numbered `S1` onwards; a later change gets a new number, never a rewrite.

`govengers/storage` is the blob storage of a govengers service: uploads, attachments, generated PDFs and exports, avatars. One interface, three backends (S3-compatible object stores, the local filesystem, memory), the helpers every upload path needs, and the observability adapters. Profile `library`, Apache 2.0, Go 1.26; govengers/standards apply.

## 1. The model

An **object** is a byte stream under a **key**, with a content type and string metadata. A `storage.Store` puts, gets (whole or a byte range), stats, deletes and lists objects. Optional capabilities are separate interfaces (`Copier`, `Presigner`), reached through package functions that fall back or report `ErrNotSupported`. An `ObservedStore` wraps any store and reports every operation to `Observer`s; the adapters turn them into metrics and spans.

```
service code ── storage.Store ── ObservedStore ── s3adapter | filesystem | memory
                     │                 └── Observers: prometheusadapter, oteladapter
                     └── helpers: ValidateKey, LimitReader, NewSHA256Reader, DetectContentType
```

The database row of the application owns the object: it records the key, the size, the content type and the digest it computed while uploading; the store only keeps the bytes. Keys are chosen by the application, never by a client.

## 2. Decisions

| ID | Decision |
|----|----------|
| S1 | One module `github.com/govengers/storage` with the backends and adapters as subpackages (`s3adapter`, `filesystem`, `memory`, `prometheusadapter`, `oteladapter`, `storagetest`). The core imports only the standard library. Module graph pruning keeps the AWS SDK, client_golang and OpenTelemetry out of the build of a consumer that does not import their adapter, as in govengers/jobs and aikido. Rejected: a nested module for `s3adapter` (own tags, `./...` in CI and govulncheck stop at the module boundary, and the AWS SDK pulls no third-party modules, see S9). |
| S2 | `Store` has five methods: `Put(ctx, key, body, *PutOptions) (*Object, error)`, `Get(ctx, key, *GetOptions) (*Reader, error)`, `Stat`, `Delete`, `List(ctx, *ListOptions) (*Page, error)`. A nil options means the defaults. `Get` returns a `*Reader` that carries the whole object's attributes and the range it yields; the caller closes it. `Delete` of a missing object is no error (S3 semantics). `List` pages by key with `StartAfter` (the last key of the previous page, `Page.Next`) and at most 1000 objects; listed objects carry key, size and modification time only, because S3 lists nothing more. No delimiter listing in v1. |
| S3 | Optional capabilities are separate interfaces: `Copier` (server-side copy) and `Presigner` (signed GET and PUT URLs). Callers use the package functions `storage.Copy` (falls back to streaming through Get and Put), `storage.PresignGet` and `storage.PresignPut` (return `ErrNotSupported`). `ObservedStore` implements both interfaces for every wrapped store and returns `ErrNotSupported` where the wrapped store lacks them, so a type assertion alone is not enough; that is why the package functions are the entry point. |
| S4 | One key rule for every backend (`ValidateKey`), the strictest of them: valid UTF-8, 1 to 1024 bytes (S3), segments separated by single slashes, every segment 1 to 255 bytes (common filesystems), not `.` or `..`, no control character, no backslash. So no key starts or ends with a slash, and none can leave a filesystem root even before `os.Root` checks it. Every method validates before any I/O and returns `ErrInvalid`. `ValidatePrefix` applies the rule to every segment of a prefix but the last, which only filters names. |
| S5 | Metadata keys are lowercase ASCII letters, digits and hyphens, values non-empty printable ASCII without surrounding spaces, at most 2 KiB together (S3's limit). They travel as `x-amz-meta-*` headers, where anything else is changed or rejected by some server or proxy (underscores are dropped by nginx, non-ASCII is mangled). Content types must parse as `type/subtype` with parameters, printable ASCII, at most 255 bytes; empty means `application/octet-stream`. |
| S6 | A `Put` is atomic on every backend: the object becomes visible once the body was read completely and stored; a failed body, a cancelled context or a body above `PutOptions.MaximumSize` (`ErrTooLarge`) leaves the previous object, or none. Concurrent puts to one key leave one whole write, never a mix. The size cap fails instead of truncating (`LimitReader`). |
| S7 | Errors: the sentinels `ErrNotFound`, `ErrInvalid`, `ErrInvalidRange`, `ErrTooLarge`, `ErrUnsupportedContentType`, `ErrNotSupported`, wrapped with the operation and the key. Errors of the AWS SDK keep only their message (LIB-010); a done context is returned as the context's error, so `errors.Is(err, context.Canceled)` holds on every backend. |
| S8 | Ranges: `GetOptions{Offset, Length}`; `Length` zero reads to the end, a range past the end is cut there, an `Offset` at or beyond the size is `ErrInvalidRange` except an `Offset` of zero, which is valid on an empty object too (S3 rejects every range on an empty object; `s3adapter` retries such a read without the range). `GetOptions.Range(size)` is the one implementation of the rule for backends. |
| S9 | The S3 client is the AWS SDK for Go v2 (`service/s3`), chosen by footprint, measured 15.11.2026 with a stat-only binary: about 7.6 MB for both it and minio-go v7.4.1, but the SDK needs 12 modules, all published by AWS, against 19 for minio-go, 11 of them from third parties (tinylib/msgp, klauspost compress/cpuid/crc32, ini, yaml, xid, go-humanize, uuid, x/crypto, x/net), which is more govulncheck surface and more update churn. minio-go also allocates a whole part buffer before reading (512 MiB for a body of unknown size unless a part size is set), always uploads a body of unknown size as multipart, and its `GetObject` reports a missing object only on the first read. The SDK is configured by hand, never with `config.LoadDefaultConfig`, which reads environment variables and files (LIB-004); credentials are static. Checksums are calculated and validated only when an operation requires them: the SDK's default sends CRC trailers in aws-chunked bodies that many S3-compatible servers reject. |
| S10 | `s3adapter.Put` buffers one part at a time. The first part is read with a growing buffer, so a small object allocates little; a body that ends within it goes up with one `PutObject` (seekable, so retries and payload signing work over plain HTTP too). A longer body becomes a multipart upload with one reused part buffer: `PartSize`, default 8 MiB, from 5 MiB to 5 GiB, at most 10000 parts (80 GB at the default). Any failure aborts the upload on a context detached from the caller's (`context.WithoutCancel`, 30 s), so a cancelled Put leaves no billed orphan parts. |
| S11 | `s3adapter.Copy` reads the source's attributes, then copies with one `CopyObject` (content type and metadata kept), and reports `ErrNotSupported` above 5 GiB, where `storage.Copy` streams instead; copying onto itself returns the attributes (S3 refuses the request). Presigning uses SigV4 query signing: `PresignGet` can override the response's Content-Disposition and Content-Type (serve untrusted uploads as attachments), `PresignPut` signs the content type as a header the client must send. Expiry defaults to 15 minutes, at most 7 days. A presigned PUT cannot enforce a size or check the content; the caller checks the stored object before using it. |
| S12 | `filesystem` keeps every object as one file `<Root>/objects/<key>`: the magic `gvstore1`, the header length as a big-endian uint32, a JSON header (content type, metadata), the content. A Put writes `<Root>/tmp/<random>`, flushes it, renames it into place and flushes the directory, so content and metadata switch together. All access goes through `os.Root`, which confines it to Root even with symlinks inside. Delete removes the directories it leaves empty; Put retries the rename when a concurrent Delete pruned the directory in between. List walks in key order by sorting each directory's entries with a slash after directory names (every key below a directory starts with its name and a slash), skips whole subtrees before `StartAfter` and stops after the page; it reads one header per listed object. Limits, documented: `a` and `a/b` cannot both exist (`ErrInvalid`), case-insensitive filesystems merge keys that differ in case, no presigning, files of a crashed Put stay in tmp. Rejected: sidecar metadata files (two renames, never atomic together), extended attributes (not on every filesystem and volume type), plain content files (no atomic content type). |
| S13 | `memory` is a map under a read-write mutex, with snapshot readers and a `Copy` that shares the immutable content. It is for tests and development; `List` sorts on every call. |
| S14 | Helpers for upload paths: `LimitReader` (fails with `ErrTooLarge` instead of truncating), `NewSHA256Reader` (digest while streaming, for content-addressed keys and integrity), `DetectContentType` (the WHATWG sniffing of `http.DetectContentType` on the first 512 bytes, checked against an allowlist of media types and `type/*` wildcards, returning a reader that replays the sniffed bytes). The sniffer never reports SVG; it is text, and rejecting it under `image/*` is the safe default. `ContextReader` lets backends stop a copy when the context ends. |
| S15 | Observability follows aikido's `llm.Observer`: `OperationStarted(ctx, *Operation) context.Context` and `OperationFinished(ctx, *Operation, *Outcome)`, started in order and finished in reverse. `Operation` names the store (`ObservedStoreOptions.Name`) and the operation, never the key: keys can carry personal data (file names), which must not reach metrics or traces (TRC-006). A get finishes when its Reader is closed, with the bytes read. `ClassifyError` maps errors to a closed set (`success`, `not_found`, `invalid`, `too_large`, `unsupported`, `cancelled`, `error`) shared by both adapters. `prometheusadapter`: `<namespace>_storage_operations_total{store,operation,outcome}`, `_operation_duration_seconds{store,operation}`, `_bytes_total{store,operation}`. `oteladapter`: one internal span `storage.<operation>` with `storage.store`, `storage.operation`, `storage.bytes`, `storage.error_class`; a failure sets the error status with the class, never the message; `ErrNotFound` is an answer and leaves the status unset. No wide-event adapter: the caller records failures on its own wide event, which already has the key and the error. |
| S16 | `storagetest.Run(t, NewStore)` is the conformance suite: round trip, defaults, overwrite, ranges, missing objects, delete, invalid arguments, size cap, failed and cancelled bodies, key-order listing with paging, copies of results, concurrent puts, snapshot readers, Copy and Copier, presigned GET and PUT sent over HTTP. Every backend and `ObservedStore` pass it. `s3adapter` passes it against `internal/s3fake`, an in-process S3 on loopback HTTP that implements the calls the adapter makes, refuses aws-chunked bodies, injects non-retryable failures and counts open multipart uploads. It does not check signatures. Rejected: gofakes3 (pulls bbolt, mgo, afero and an old x/tools into go.mod, no fault injection), a Docker S3 in CI (minutes per run, and the RustFS images had startup and auth defects in 2026). |
| S17 | Fast tests: no database, no sleeps, no network beyond loopback `httptest`, injected failures are 403s the SDK does not retry, so no backoff runs. `just test` takes about 7 s cold and under 1 s warm. The coverage gate excludes the test harnesses `internal/s3fake` and `storagetest`, which run from the backends' tests. |

## 3. Not in v1, and when to add it

- Delimiter listing (folders and common prefixes): when a UI browses a tree.
- Presigned POST policies: when browsers upload directly and the size must be capped by the store.
- Credential providers beyond static keys (IRSA, instance roles, the AWS default chain): when a service runs on AWS with workload identity.
- Multipart copy above 5 GiB, server-side encryption options, versioning, object lock: when a consumer needs them.
- An HTTP helper that maps `Range` and conditional headers to `GetOptions`: when the second service writes the same download handler.
- A cleaner for crash leftovers in the filesystem store's tmp directory, and a wide-event adapter.
- A nightly compatibility job against a real S3-compatible server (signatures are not checked by the fake).
