# S3

`s3adapter.Store` works with AWS S3 and S3-compatible servers (MinIO, RustFS, Ceph RGW, Garage, cloud object storage that speaks SigV4). It is a `storage.Store`, `storage.Copier` and `storage.Presigner`.

## Options

| Field | Meaning |
|-------|---------|
| `Endpoint` | URL with scheme: `https://s3.eu-central-1.amazonaws.com`, `http://rustfs.storage.svc:9000`; required |
| `Region` | signs requests; empty is `us-east-1`, what most compatible servers expect |
| `Bucket` | required; it must exist, `New` makes no request |
| `AccessKeyID`, `SecretAccessKey`, `SessionToken` | static credentials; the first two are required |
| `PathStyle` | `http://host/bucket/key` instead of `http://bucket.host/key`; self-hosted servers usually need it, AWS does not |
| `PartSize` | multipart part size and the buffer of one Put; default 8 MiB, 5 MiB to 5 GiB |
| `HTTPClient` | nil is the SDK's client; pass `&http.Client{Transport: otelhttp.NewTransport(http.DefaultTransport)}` to trace requests. Leave `Timeout` zero; the context bounds each call |

The client is the AWS SDK for Go v2, configured by hand: it reads no environment variables or shared config files. Checksums are only sent where an operation requires them, because the SDK's newer default (CRC trailers in aws-chunked bodies) is rejected by many compatible servers.

## Uploads

A body that fits into one part goes up with one `PutObject`. A longer one becomes a multipart upload; one part buffer is reused, so memory per running Put is one part. Any failure, a cancelled context included, aborts the upload, so no parts are left behind. A body may hold at most 10000 parts: 80 GB at the default part size; raise `PartSize` for larger objects. Still, add a lifecycle rule that aborts incomplete multipart uploads after a day: a process killed mid-upload cannot abort.

## Copy and presigning

`Copy` copies with one `CopyObject` and keeps the content type and metadata. It is bound to the revision its `HeadObject` read (`x-amz-copy-source-if-match`), so the attributes it returns describe the copied content even when the source is replaced meanwhile; above 5 GiB it reports `ErrNotSupported` and `storage.Copy` streams the object instead. `PresignGet` and `PresignPut` sign requests with SigV4 query parameters; see [Uploads-and-Downloads](Uploads-and-Downloads.md#presigned-urls). The URL carries the endpoint as configured: a browser must reach that host, so use the public endpoint, not a cluster-internal one, for presigned URLs (a second Store with the public endpoint is fine; it makes no request until used).

## Errors

`NoSuchKey` and a 404 on `HEAD` are `storage.ErrNotFound`, `InvalidRange` is `storage.ErrInvalidRange`. A missing bucket is a plain error, not `ErrNotFound`. Other SDK errors keep their message (`AccessDenied`, the request ID) but not their type.
